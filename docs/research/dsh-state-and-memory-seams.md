# DSH state & memory seams — research for a thought-graph design

Read-only research over `upstream/deepseek-harness`. All claims anchored to `path:line`. English `.md` only.

## 1. Session projections (`ctx.sessionProjections`)

Registry: `packages/session/session-projection/src/index.ts`.

- Registration contract, `ProjectionDefinition` (`:48-93`): `key` (a `SessionProjectionStateMap` entry), `stateSchema: ZodType<S>` (validates persisted state before seeding a fold), `init(header, inheritedEventCount): S`, `apply(state, event): S` (pure sync fold; MUST return the same reference when uninterested — `Object.is` gates all downstream work, `:66`), optional `wire: { viewSchema, view(state) }` (client-visible read side; omit for host-only units, `:72-85`), `stateVersion: number` (persisted-cache invalidation version, `:86-92`).
- `register()` (`:233-293`) validates `stateVersion` is a non-negative integer (`:270-272`) and — load-bearing — **refuses to let two registrants share a key at different `stateVersion`s** (`:279-281`), throwing. Registration is a Cordis effect; disposal removes the key (and cached cells) from future drives (`:225-232`).
- Fold-over-events mechanic: `drive()` (`:657-704`) is called once per committed `session/event`; it passes the event through every registered unit's `apply`, diffs the returned state by `Object.is`, and only recomputes+publishes the `wire.view` when the state reference actually changed (`:680-700`). Comment at `:12-15`: **"Whole-value event rule (load-bearing): a state-carrying log event MUST carry the complete post-change state, never a bare delta."**
- Restore on resume/replay: `restore()` (`:495-540`) seeds each unit from its persisted checkpoint row (`ProjectionCheckpointRow = { ver, seq, val }`) when the row's `ver` matches the live `stateVersion` and its `seq` lies within `[baseSeq-1, endSeq]` (`:509-513`); otherwise it re-folds from `init` over the full log, and a mismatched/missing row combined with `baseSeq > 0` **throws**, forcing a full re-read from seq 0 (`:514-519`). `restoreFloor()` (`:409-435`) computes the log-read starting offset needed so every registered unit's row is verifiably still valid (detects a shrunk/truncated log). `hydrate()` (`:552-595`) is the entry point that installs restored state onto a live `Session`.
- Versioning rule, from the field doc (`:86-92`): **bump `stateVersion` whenever the serialized state shape or fold semantics change** — a version bump invalidates old persisted-cache rows instead of forward-applying them into garbage.
- Real examples:
  - `packages/todo/tool-todo/src/index.ts:123-134` — `todos` unit: `init: () => null`, `apply` matches `todo/write` (replace) and `turn/start` (reset to `null`), `stateVersion: 2`.
  - `packages/goal/goal/src/index.ts` (types in `packages/goal/goal/src/types.ts:128-141`) — `goal` unit: state is `GoalProjectionState { current, seenGoalIds, failure }`, folded from `goal/change` events (see §3).

## 2. Adding a new SessionEvent type — end to end

- Declare the payload via declaration merging into `SessionEventMap` (`packages/core/session/src/types.ts:281-428`), e.g. `packages/todo/tool-todo/src/types.ts:29-33`:
  ```ts
  declare module '@deepseek-ai/dsh-session/types' {
    interface SessionEventMap {
      'todo/write': { todos: TodoItem[] }
    }
  }
  ```
- The event envelope (`SessionEvent<T>`, `types.ts:493-516`) auto-adds `seq`, `time`, `data`, optional `ignorable`, and (only for `SurfaceEventType`s) `surfaceOp`/`sourceEventSeqs`. A plugin does **not** hand-build this — it calls `session.append(type, data, …)` (used at `packages/todo/tool-todo/src/index.ts:199`: `exec.agent.session.append('todo/write', { todos })`).
- Register the type name in `KNOWN_SESSION_EVENT_TYPES` (`packages/core/session/src/known-event-types.ts:22-70`, includes `'todo/write'` at `:66`) — this file is **generated** by `scripts/gen-persistence-catalog.ts` and verified by `verify-persistence-catalog` (doc-sync), so a new event type must flow through that generator, not be hand-edited (`known-event-types.ts:1-4`). Purpose (`:6-19`): a persistence reader refuses to interpret a log containing an unrecognized type unless it carries `ignorable: true` — decide up front whether the new event is safe to skip on an older reader.
- If the event should be replayable into visible/derived state, register a `sessionProjections` unit (§1) whose `apply` matches on the new `type` — this is what makes the event's effect "state," not just a log entry.
- If the event should participate in relational log invariants (ordering, turn/step scoping, etc.), add a case to the invariant companion, e.g. `packages/todo/tool-todo/src/invariant.ts:55-58` requires `todo/write` to be appended only inside an open turn.
- Client visibility requires a `wire.viewSchema` + `view()` on the projection (§1) — no wire, no `snapshot()`/`onChanged()` visibility (`session-projection/src/index.ts:73-85`, `:338-352`).
- **What breaks with a plain mutable variable instead**: it is not in `session/event`s, so (a) it vanishes on process restart / resume (no `restore()` seed, no cold `viewCheckpoint()`), (b) `session.snapshotEvents()`/replay never reproduces it — two readers of the same log diverge, (c) it is invisible to `ctx.sessionProjections.snapshot()`/`onChanged()` consumers (UI, other plugins), (d) it is not compaction-aware — nothing marks it `ignorable` or protects it, and a fork/subagent seed (§8) that copies only session events never carries it. This is exactly the substrate's stated invariant: **"model-visible means logged."**

## 3. `ctx.goals` — data model, lifecycle, `goal-round-driver`

- Durable payload (`packages/goal/goal/src/domain.ts:23-44`): `GoalSnapshotChangeMeta { kind:'goal/change', version:1, operation, goal: GoalSnapshot, roundsStarted, createdAt, updatedAt }` or a tombstone `GoalClearChangeMeta { operation:'clear', cleared: GoalRef, clearedAt }`. `GoalSnapshot` (`packages/goal/goal/src/types.ts:59-69`): `{ id, revision, objective, phase: 'active'|'paused'|'blocked'|'complete', blockedReason?, maxGoalRounds }`.
- Projection state (`types.ts:107-126`): `GoalProjectionState { current: GoalProjection | null, seenGoalIds: GoalId[], failure: string | null }` — **`current` is a single slot: one goal per session**, not a collection. `seenGoalIds` exists only to reject id reuse after a clear (`:122-123`).
- Lifecycle operations: `create → edit/pause/resume/block/complete`, plus `clear` (tombstone, `domain.ts:14-21`). Activation (`armed`/`disarmed`, `types.ts:72-86`) is explicitly **process-local, never persisted** — a resumed session's durable phase survives, but automatic-continuation eligibility resets.
- `goal-round-driver` (`packages/goal/goal-round-driver/src/index.ts`) is a same-session continuation scheduler, not a projection owner. It reads `ctx.goals.get(agent)` (`:97-100`) and, when `goal.phase==='active' && goal.activation==='armed'` and `roundsStarted < maxGoalRounds` (`:164-172`), synthesizes one `user/message` with `source:{kind:'goal', goalId, revision, round}` (`:174-179`) and pushes it via `agent.followup()`. Round admission is race-fenced: a queued/claimed/admitted `RoundAttempt` is tracked and validated again at `agent/pre-step` (`:360-425`) against the live goal ref so a stale or superseded round is rejected. Exceeding `maxGoalRounds` calls `ctx.goals.block(...)` (`:166-171`). A user-visible cancel while a round is queued pauses the goal (`:264-278`). **Conclusion: exactly one goal can be current per session; concurrency is per-round scheduling of that one goal, never several coexisting goals.**

## 4. `ctx.todo` — data model, per-turn reset

- Payload: `TodoItem { content: string; status: 'pending'|'in_progress'|'completed' }` (`packages/todo/tool-todo/src/types.ts:22-26`) — deliberately **no id**; the whole list is replaced on every `todo_write` call (last-write-wins, `:12-19`).
- Model tool `todo_write` (`packages/todo/tool-todo/src/index.ts:135-211`) validates uniqueness of `content`, at most one `in_progress` unless `allowParallelInProgress` (`:80-100`), then appends `todo/write` (`:199`).
- Projection fold (`:123-134`): `init: () => null`; `apply`: `todo/write` → `event.data.todos`; **`turn/start` → `null`** (clears the list every new turn); any other event → same reference unchanged. Comment (`:119-122`): "cleared by the next turn/start (turn/end keeps the finished checklist visible)". So the todo list is **ephemeral per turn** by construction — it is not "cleared per turn" by a special reset event, it is re-derived to `null` the moment a new turn opens, and only re-populated when the model calls `todo_write` again.
- Invariant: `packages/todo/tool-todo/src/invariant.ts:55-58` — `todo/write` must be appended inside an open turn (`trace.open`), else it fails the log's relational invariants.

## 5. Compaction & context — what survives, what a plugin can protect

- Compaction only ever replaces **surface** nodes. Surface event types are exactly `system/message, developer/message, user/message, assistant/message, tool/result` (`packages/core/session/src/types.ts:439-444`). Everything else — `todo/write`, `goal/change`, `compaction/*` markers themselves, `request/header`, etc. — is a **log-only event with no `surfaceOp`**, and `SurfaceIntent` types forbid `surfaceOp`/`sourceEventSeqs` on non-surface events at the type level (`types.ts:470-478`, `:512-515`). **A `sessionProjections` unit folding a log-only event type is therefore immune to compaction's surface replacement — compaction cannot shadow it because it was never part of the surface.**
- Mechanics (`packages/compaction/compaction/src/index.ts` + `types.ts`): a compaction pass appends `compaction/start` (lock, `types.ts:20-24`), computes a summary, appends `compaction/summary` (`:34-67`, carries `shadowedRange`, `shadowedSeqs`, `shadowedTokenCount`, model/provider facts, optional `rawOutput`), then a `user/message` with `surfaceOp: {op:'replace', startSeq, endSeq}` that actually shadows the surface nodes, then `compaction/end` (`:68-72`). `CompactionEngine.compactRegion` (`compaction/src/index.ts:168-193`) is the primitive: "Forcibly compact a range of surface nodes into a single summary node" — edges must be tool-call-balanced (`toolPairingBalancedBefore/After`).
- **Nothing is deleted.** The original events remain in the durable log at their `seq`; only the model-visible *surface projection* is replaced. This is explicit in `compaction/prune`'s doc (`types.ts:74-89`, "shadow price" protocol) and is the whole premise of the proposed (not implemented) `.agents/notes/proposed/feature/2026-07-06-recallable-compaction.md`, which states the problem plainly: *"Compaction is irreversible from the model's current context... the append-only log holds every byte"* — i.e. today, once shadowed, a surface span is gone from what the model sees (no in-loop recall tool exists yet), but the bytes persist for a future reader.
- `packages/context/**` is not a compaction/history-trimming layer; its packages (`agent-instructions`, `file-reference`, `file-reference-local`, `session-reference`, `time-context`, `tmux-context`) each register small `sessionProjections`/message-injection units that add contextual content (file references, time, tmux state) into the surface — orthogonal to compaction.
- **Implication for a thought graph:** a projection built purely from log-only (non-surface) `SessionEvent`s survives every compaction pass unconditionally — that is the substrate's one built-in "compaction-proof" home for durable state.

## 6. `packages/spill/**` and `packages/workspace/**`

- `packages/spill/spill/src/index.ts`: `SpillStore` is an abstract Cordis `Service` (`ctx.spillStore`) with exactly one method, `saveText(input: SaveTextSpill): Promise<SpillRef>` (`:45-56`). Deliberately minimal — "owns NO retention policy... NO tool-result replacement... NO retrieval or search API" (`:8-12`). It is a **write-only, session-scoped** blob sink for oversized text (e.g., large tool output), not a queryable store; there is no read/list API in this package.
- `packages/spill/spill-local/src/store.ts`: default root is `mkdtempSync(join(tmpdir(), ...))` (`:37`) unless configured otherwise; files are written under a per-session directory (`:80`) with randomized names (`:110`) — i.e. its default is a **temp directory**, not durable `$DSH_HOME` storage, unless a deployment overrides the root.
- `packages/workspace/workspace/src/types.ts`: `Workspace` (`:52-70`) is a **directory registry** — `{ id, path (realpath), title, createdAt, ... }` — that tracks which sessions ran in which cwd (`SessionActivityKind`/`SessionActivityItem`, `:24-49`). It is not an artifact store at all.
- **Conclusion: neither is a legitimate home for durable, model-visible thought-graph state.** Spill is for offloading large ephemeral text out of context (with no guaranteed retrieval path back), and workspace is directory/session bookkeeping. Durable structured state belongs in `sessionProjections` (session-scoped, replayable) or `ctx.storage` (§7, cross-session).

## 7. Cross-session persistence — `ctx.storage`

`packages/storage/storage/src/index.ts`: `Storage` service (`ctx.storage`) is a hub: `backend: BackendRegistry` (named backends registered under a string key, `:49`, `:64-93`) plus mountable `StorageForms` (domain-form facilities reached as `ctx.storage.<form>`, `:41,64-87`). The hub does no I/O itself (`:3-4`).

- Domain form (`packages/storage/storage-domain/src/domain.ts`): `Domain<S>` exposes `global: DomainGlobal<G>` (`get()`/`set()`, `:19-35`) and `table<N>(name): KvTable<K,V>` (`get`, `entries()`, `keys()`, `size`, `put`, `delete`, `update`, `:42-90`). Every write is queued on a **single per-domain write chain**, awaits backend durability, *then* mutates in-memory state, *then* emits `domain/changed` (`:6-8`, `:307-313`) — a rejected backend write never diverges memory from disk.
- Concrete backends: `packages/storage/storage-json/src/index.ts` — one JSON file (or per-record directory) per "unit" under a **configured `root`** (`Config.root`, `:28-36`, **no default on purpose** — "a `process.cwd()` fallback would scatter unit files wherever the process happens to start; assemblies state the location explicitly", `:24-27`); registers via `ctx.storage.backend.register('json', backend)` (`:112`). `packages/storage/storage-sqlite/src/index.ts` is the SQLite-backed alternative (not read in detail here).
- `$DSH_HOME` resolution: `packages/*/home-paths/src/index.ts` — `DSH_HOME_DIR_NAME = '.dsh'` (`:11`), `DSH_HOME_ENV = 'DSH_HOME'` (`:17`), `defaultDshHome()` returns `~/.dsh` (`:58-60`), precedence explicit path → `$DSH_HOME` → `~/.dsh`.
- **Could NOT verify**: I found no concrete assembly/config wiring the `storage-json`/`storage-sqlite` `root` to a specific `$DSH_HOME/storages` subpath in this pass (grepped `apps/`, `packages/preset`, `packages/boot`, `scripts` for `storage-json`/`storages` usage — no hits besides unrelated `.storages` entries in `scripts/translation-pairing.ts` and an Electron `storages:` array in `apps/desktop/src/platform-view.ts:258` that is unrelated browser-partition config). The mechanism (hub + backend + domain form) is real and durable across sessions by construction (JSON/SQLite files on disk keyed by unit/table/key, independent of any one `Session`'s log); the exact default on-disk path a plugin gets "for free" is deployment-assembly-specific and needs a follow-up grep in the actual app/profile YAML once that's not blocked from touching other in-flight work.

## 8. Subagent context contract (`packages/subagent/**`)

- `packages/subagent/subagent/src/child-agent.ts`:
  - `resolveChildAgentOptions` (`:99-120`) — a child **inherits provider/model/reasoningEffort/maxTokens** from the parent's live request header (falling back to creation options, `:69-86`) unless the child call overrides them; changing route drops the inherited reasoning effort (`:117-118`).
  - `childSessionMeta` (`:139-157`) — durable child `SessionHeader` fields set from the parent: `cwd` (if any), `agentPreset` (read from the parent's **live** composition, not its header, so it reflects mid-session preset switches — comment `:128-133`), `parentSession: parentHeader.id`, `origin:'subagent'`, `delegationDepth: childDepth` (parent depth + 1, capped, `resolveChildDepth` `:50-59`).
  - `isSeeded` (`:136,142,150`) marks whether the child's log carries an inherited event prefix from the parent — **this is opt-in per call site**, not automatic; a plain new subagent session starts with an empty log plus this metadata (no inherited `sessionProjections` state) unless the caller explicitly builds a fork seed (`buildForkSeed`, found in `packages/core/session/src/fork.ts`, used by `/fork`-style commands — not exercised generically by the default subagent spawn path in the files read here).
  - Communication back to the parent is via ordinary model-visible messages, not shared state: `packages/subagent/subagent/src/continuation-messages.ts:14-42` defines `AgentMessageSource` (`kind:'agent-message', form:'relay'`) for a message one live agent sends another, and `SubagentSettledMessageSource` (`kind:'subagent-settled', form:'notice'`) for the runtime's own account of how a child ended — both are just `MessageSourceMap` entries riding ordinary `user/message`/tool-result events.
- **Conclusion:** a subagent inherits routing/composition/lineage metadata and (only if the spawn path opts into a seed) a literal prefix of the parent's session log — never a live handle to the parent's `sessionProjections` state. If a thought graph should be shareable with subagents, it must either (a) be serialized into the seeded log prefix, (b) be re-stated as prompt content in the spawning message, or (c) live in `ctx.storage` (§7) where any session — parent or child — can open the same durable unit by a shared key.

## Design constraints for a thought graph

1. **Forced**: any model-visible thought-graph node must be a `SessionEvent` (declared via `SessionEventMap` merge + `session.append()`), or it is not durable, not replayable, and not resumable — plain variables silently break on restart/resume (§2).
2. **Forced**: to make it *state* (not just a log entry), register a `sessionProjections` unit with a pure `apply` fold; state must be plain JSON (persisted-cache precondition, `session-projection/src/index.ts:46`) and `apply` must return the same reference when unaffected (`Object.is` gate).
3. **Given for free**: log-only (non-surface) events are automatically immune to compaction's surface-replace shadowing (§5) — this is the natural mechanism for making PERSISTENT graph nodes survive compaction; no extra protection code is needed as long as the thought-graph event type is never given a `surfaceOp`.
4. **Given for free**: EPHEMERAL, per-turn-scoped state is a solved pattern — fold `turn/start` (or `turn/end`) to reset projection state to empty/null, exactly like `todos` (§4). No bespoke "clear" event needed.
5. **Forced**: versioning discipline — any change to a node's persisted shape or fold semantics requires bumping `stateVersion`, and two registrants can never share a projection key at different `stateVersion`s (registry throws) — a thought-graph projection's schema evolution must be planned around this.
6. **Forced**: adding the event type means threading it through `KNOWN_SESSION_EVENT_TYPES` (generated catalog) and deciding its `ignorable` marker, plus (if it should participate in ordering rules) an invariant-companion case — this is process overhead per new event type, favoring **one generic thought-graph event type carrying a node/edge payload** over many bespoke event types.
7. **Forbidden/discouraged as primary home**: `spill` (write-only, defaults to a temp dir, no retrieval API) and `workspace` (directory registry only) are not fit for durable, queryable graph data (§6); cross-session durability, if needed, must go through `ctx.storage`'s domain/KV form (§7), which is a separate seam from the session log and does not participate in session replay/compaction at all.
8. **Forced**: subagents get **no automatic access** to a parent's thought graph — sharing it requires either serializing relevant nodes into the child's seed history, restating them as message content, or having both sessions open the same `ctx.storage` unit by a shared key (§8); a design that assumes subagents "just see" the graph is wrong.
