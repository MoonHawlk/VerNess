# WS-B — Teams and multiple tasks: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. Read
> `2026-09-26-00-master-plan.md` first. Requires WS-A Task 1 (`npm test`).

**Goal:** Team runs that really overlap when asked to, stop or skip predictably when a task fails,
can be inspected after the fact, and can be started ad hoc from one line.

**Architecture:** The team runner (`scripts/lib/teams.mjs`) already models tasks, members,
`dependsOn` and a concurrency limit, but executes each task through the **synchronous** `dsh()`
runner, so `Promise.race` never overlaps anything. This plan adds an async twin `dshAsync()`
(same shell-free spawn), injects it through `ctx`, and makes `runTeam` testable by accepting an
output directory and a runner. The failure policy and status are data on the run: `summary.json`
beside `summary.md`.

**Tech stack:** Node ESM, `node:child_process.spawn`, `node:test`.

**Spec:** `docs/07-COMMAND-LAYER.md` §"Teams and multiple tasks" and challenge #10 (failure
semantics); `teams/README.md`; ADR-0008.

## Global Constraints
Inherit the master plan. Also:
- The async runner must spawn `process.execPath <dsh entry>` with **no shell** (same reason as T-145).
- Default failure policy is `stop`. A task whose dependency failed or was skipped is `skipped` and is
  **never** run with partial context.
- `summary.json` is the machine-readable record. The dashboard and `/team status` read it, never parse `summary.md`.

## Review Focus
1. A task that exits 0 but prints nothing (a model that answered with nothing) is `done`, but its
   dependents get no upstream context. Log a warning `empty output`. Test in Task 3.
2. `retry-once` must not retry a task that was cancelled (ctrl+c). Treat signal exits as `cancelled`.
3. Two tasks writing the same `persona-<id>.patch.yml` overlay concurrently. The overlay is
   deterministic per persona, so the file content is identical. Write it to a temp name and rename
   atomically. Task 1 handles it.
4. `--parallel 0`, `--parallel abc` → clamp to 1 with a warning, never hang.
5. Ctrl+c during a parallel run must kill every child it started. Task 1 tracks the children.

Extract the lookup at the top of `dsh()` into:

```js
/** @returns {string|null} the substrate's JS entry, cached; null when it cannot be resolved. */
function resolveDshEntry() {
  if (dshEntry !== undefined) return dshEntry
  const root = npmRootGlobal()
  const dir = root === undefined ? undefined : join(root, '@deepseek-ai', 'dsh')
  try {
    const bin = JSON.parse(readFileSync(join(dir, 'package.json'), 'utf8')).bin
    const rel = typeof bin === 'string' ? bin : bin?.dsh
    dshEntry = rel === undefined ? null : join(dir, rel)
    if (dshEntry !== null && !existsSync(dshEntry)) dshEntry = null
  } catch { dshEntry = null }
  return dshEntry
}
```

and make `dsh()` call `resolveDshEntry()`. Then add:

```js
/** Children started by dshAsync, so ctrl+c can take them all down. */
const liveChildren = new Set()
process.once('SIGINT', () => { for (const c of liveChildren) c.kill('SIGINT') })

/**
 * The async twin of {@link dsh}: same shell-free spawn, but it does not block the event loop, so
 * several substrate runs can overlap (the team runner's --parallel).
 * @param {string[]} args - arguments for dsh.
 * @param {{env?: Record<string,string>, capture?: boolean, signal?: AbortSignal}} [opts] - options.
 * @returns {Promise<{code: number, out: string, signal?: string}>} exit status and captured output.
 */
function dshAsync(args, opts = {}) {
  const entry = resolveDshEntry()
  if (entry === null) return Promise.resolve(sh('dsh', args, opts))
  return new Promise(resolvePromise => {
    const child = spawn(process.execPath, [entry, ...args], {
      cwd: REPO,
      env: { ...process.env, ...opts.env },
      stdio: opts.capture === true ? ['ignore', 'pipe', 'pipe'] : 'inherit',
      signal: opts.signal,
    })
    liveChildren.add(child)
    let out = ''
    child.stdout?.setEncoding('utf8').on('data', d => { out += d })
    child.stderr?.setEncoding('utf8').on('data', d => { out += d })
    child.on('error', e => { liveChildren.delete(child); resolvePromise({ code: 1, out: String(e.message) }) })
    child.on('close', (code, signal) => {
      liveChildren.delete(child)
      resolvePromise({ code: code ?? 1, out: out.trim(), ...(signal === null ? {} : { signal }) })
    })
  })
}
```

Add `dshAsync,` to the object `makeCtx` returns, next to `dsh`.

### Task 3: Failure policy (T-167, remaining part)

**Files:**
- Modify: `scripts/lib/teams.mjs` (`loadTeams` reads `onFailure`; the scheduler honours it; `validateTeam` rejects unknown values)
- Modify: `teams/README.md` (document the field), `teams/analysis-review.json` (add `"onFailure": "stop"` explicitly)
- Test: `scripts/test/teams.failure.test.mjs`

**Interfaces:**
- Team field `onFailure: 'stop'|'skip'|'retry-once'` (default `stop`). A task may override it with its own `onFailure`.
  - `stop`: when a task fails, no new task starts. Running tasks finish. Every task not yet started becomes `skipped` with `reason: 'stopped after <id> failed'`.
  - `skip`: dependents of the failed task (transitively) are `skipped`. Unrelated tasks continue.
  - `retry-once`: the task runs once more. If the retry fails, `skip` semantics apply. A `cancelled` task is never retried.
- `runTeam` resolves to `{dir, results}`; `results` include `skipped` records `{id, persona, status: 'skipped', reason, code: null, seconds: 0}`.
- `/team run` exits 1 if any task is `failed` or `skipped`.

```js
/**
 * Every recorded team run, newest first. Stamps are ISO times with `:`/`.` replaced, so they sort
 * lexically; a directory that is not a stamp sorts last.
 * @param {string} [root] - the runs directory.
 * @returns {{team: string, stamp: string, dir: string, summary?: object}[]} the runs.
 */
export function listRuns(root = join(REPO, '.verness', 'runs')) {
  if (!existsSync(root)) return []
  const out = []
  for (const team of readdirSync(root)) {
    let stamps = []
    try { stamps = readdirSync(join(root, team)) } catch { continue }
    for (const stamp of stamps) {
      const dir = join(root, team, stamp)
      let summary
      try { summary = JSON.parse(readFileSync(join(dir, 'summary.json'), 'utf8')) } catch { /* legacy run */ }
      out.push({ team, stamp, dir, summary })
    }
  }
  const isStamp = s => /^\d{4}-\d\d-\d\dT/.test(s)
  return out.sort((a, b) => (isStamp(b.stamp) - isStamp(a.stamp)) || b.stamp.localeCompare(a.stamp))
}

/** @param {string} [teamId] @param {string} [root] @returns {object|undefined} the newest run. */
export const latestRun = (teamId, root) => listRuns(root).find(r => teamId === undefined || r.team === teamId)
```

```js
/**
 * An ad-hoc task list: `/task add` queues, `/task run` executes the queue as a one-off team, so
 * multi-task work does not need a teams/<id>.json first.
 * @module scripts/lib/taskqueue
 */

import { mkdirSync, readFileSync, writeFileSync } from 'node:fs'
import { dirname } from 'node:path'

/** @param {string} file @returns {{next: number, tasks: object[]}} the queue. */
export function readQueue(file) {
  try { return JSON.parse(readFileSync(file, 'utf8')) } catch { return { next: 1, tasks: [] } }
}

/** @param {string} file @param {object} q */
function writeQueue(file, q) {
  mkdirSync(dirname(file), { recursive: true })
  writeFileSync(file, `${JSON.stringify(q, null, 2)}\n`, 'utf8')
}

/** @param {string} file @param {{prompt: string, persona?: string, dependsOn?: string[]}} t @returns {string} the new id. */
export function addTask(file, t) {
  const q = readQueue(file)
  const id = `q${q.next}`
  q.next++
  q.tasks.push({ id, prompt: t.prompt, persona: t.persona, dependsOn: t.dependsOn ?? [], added: new Date().toISOString() })
  writeQueue(file, q)
  return id
}

/** @param {string} file @param {string} id @returns {boolean} whether it existed. */
export function cancelTask(file, id) {
  const q = readQueue(file)
  const n = q.tasks.length
  q.tasks = q.tasks.filter(t => t.id !== id)
  writeQueue(file, q)
  return q.tasks.length < n
}

/** @param {string} file @param {string[]} ids - tasks to drop (the ones that finished). */
export function removeTasks(file, ids) {
  const q = readQueue(file)
  q.tasks = q.tasks.filter(t => !ids.includes(t.id))
  writeQueue(file, q)
}

/**
 * @param {{tasks: object[]}} q - the queue.
 * @param {string} activePersonaId - persona for tasks that name none.
 * @returns {object} a team in the shape `loadTeams` produces.
 */
export function queueAsTeam(q, activePersonaId) {
  const personas = [...new Set(q.tasks.map(t => t.persona ?? activePersonaId))]
  return {
    id: 'adhoc', name: 'ad-hoc task queue', description: '', concurrency: 1, onFailure: 'skip',
    members: personas.map(p => ({ role: p, persona: p })),
    tasks: q.tasks.map(t => ({ id: t.id, prompt: t.prompt, member: t.persona ?? activePersonaId, dependsOn: t.dependsOn, onFailure: undefined })),
  }
}
```

The ad-hoc queue defaults to `onFailure: 'skip'` on purpose: queued tasks are usually unrelated.

```js
/**
 * The team router's question: which persona owns this task? A choice over persona ids, never over
 * more than 8 options (high-cardinality choice is the documented weak spot).
 * @param {Map<string, {id: string, name?: string, description?: string}>} personas - candidates.

export function personaQuestion(personas) {
```
